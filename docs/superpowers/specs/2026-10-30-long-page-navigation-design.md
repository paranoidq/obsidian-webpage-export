# 长页面导出：层级导航与表格样式修正（设计草案）

状态：已实现（2026-10-31）。以下保留设计背景与方案取舍，实际实现与验证记录见第 8 节。

## 1. 背景

### 1.1 要解决的问题

交互站点导出（combine as single file）分享到微信等 App 后有两个问题：

1. 微信会把文件改成 `content://com.tencent.mm.external.fileprovider/.../xxx_m.html`。首页能打开，但链接无法跳转到二级页面。
2. 部分 App 的内置浏览器里样式丢失。

### 1.2 根因

链接无法跳转的原因在 `src/frontend/main/website.ts` 第 58 行：

```ts
public isHttp: boolean = window.location.protocol != "file:";
```

模式只靠协议判断。`content:` 被当成 http 模式，于是去 `fetch("metadata.json")`，并让浏览器按相对路径跳转到不存在的兄弟文件；`pushState` 在这类来源下还可能抛安全异常。

样式丢失只是推断，尚未验证：主题类（`theme-light` 等）由 JS 在运行时加到 `<body>`，而元数据要先经 JS 解码（gzip 用到 `DecompressionStream`），禁用或不支持这些能力的 App 里主题变量就不生效。另外 Obsidian 主题常用 `:is()`、`:has()`、嵌套等较新的 CSS，老内核会整条规则丢掉。

### 1.3 已完成的部分

上一轮已经加了「长页面」导出：所有笔记合并成一个无脚本的 HTML，只用 `#锚点` 链接，主题类在导出时写进 `<body class>`；导出弹窗和设置页里有「导出形式」（长页面 / 交互站点）和「长页面样式」（手机 / PC）两个选项。实现在 `src/plugin/website/long-page.ts`。

## 2. 目前长页面的两个缺陷

### 2.1 导航是平铺的

目前目录只是按 BFS 顺序排的一层列表，所有章节连续铺在一页里。入口文件里的标题、嵌套列表和 `[[链接]]` 形成的层级完全丢了。

### 2.2 表格样式变了

长页面生成时，我把每个 `<table>` 包进了新的 `div.lp-table-scroll`，并加了 CSS 覆盖。可能的原因有三个，还没用真实主题验证：

- 多了一层父元素。Obsidian 阅读视图里表格原本直接位于 `div.el-table` 内，主题若写了 `.el-table > table` 之类的子选择器，多一层就会失效。
- 给包裹层内的表格加了 `margin: 0 !important`，覆盖了主题的表格间距。
- 手机样式给单元格加了 `min-width: 6em`。

之前的浏览器验证用的是自己编的 CSS，没有覆盖这类主题规则，所以没发现。

## 3. 方案

### 3.1 导航：复用已有的入口层级树

`src/plugin/features/cascade-content-tree.ts` 已经能把入口文件解析成树：

- 标题（`#`～`######`）按层级嵌套。
- 列表项按缩进嵌套，带 `[[链接]]` 或 `[](链接)` 的列表项指向对应页面，其余作为分组节点。
- 保持入口文件里的顺序、标题文字和图标。

交互站点的侧边栏用的就是这棵树。长页面直接用同一棵树生成导航，层级与入口文件一致。

### 3.2 展示方式：一次显示一篇，导航切换

- 所有页面仍然内嵌在同一个 HTML 里，每篇一个 `<section>`。
- 点导航项时只显示对应的 section，不再整篇连续铺开。
- 目录只反映主入口的显式层级，当前项高亮。文档依靠目录与正文引用串联，不生成「上一篇 / 下一篇」。
- 树节点可折叠。叶子是页面的节点直接跳转；叶子是标题（`页面#标题`）的节点跳转到页面并滚动到该标题。

### 3.3 切换机制

- 只用 `location.hash`（如 `#/页面id` 或 `#页面id:标题id`）和一小段内联脚本。
- 不用 `fetch`、不用 `history.pushState`、不解压数据，所以不受 `content://` 限制。
- 脚本只负责：根据 hash 显示/隐藏 section、高亮导航、同步展开状态。
- 页面内的链接继续用 `#锚点`；指向其他页面的链接改成对应的 hash 路由。

### 3.4 降级（脚本不可用时）

- section 全部显示（即现在的堆叠形式），导航树里的每一项是普通的 `#锚点` 链接。
- 仍然能读、能跳转，只是不再「一次一篇」。
- 做法：默认 CSS 就是堆叠；脚本运行后给 `<html>` 加上标记类，再启用「只显示当前」的规则。

### 3.5 桌面与手机（响应式）

同一个 HTML 自动按视口宽度适配；不再选择手机或 PC 导出样式，断点为 760px。

| | 窄屏（自动） | 宽屏（自动） |
|---|---|---|
| 导航 | 悬浮按钮拉出抽屉，选中后自动收起 | 左侧固定侧栏，可折叠 |
| 正文 | 通栏，行高加大，代码自动换行 | 居中阅读栏 |

### 3.6 不在入口层级里的页面

目录只收录主入口文件中显式编排的节点，不从正文引用推导层级。

未出现在主入口目录中的页面继续内嵌导出，能够通过文档之间的引用、直接锚点和浏览器前进后退访问；不挂到引用它的目录节点下，也不增加「其他」分组或目录末尾补项。目录为空时，不用导出页面列表补齐。

### 3.7 表格样式修正

- 不再给 `<table>` 增加包裹层，保持原有 DOM。
- 不再对表格加 `margin` 覆盖，也不再加 `min-width`。
- 为避免表格撑宽页面，只对表格的**原有父容器**设置 `overflow-x: auto; max-width: 100%`。
- 若验证后发现某些主题下仍需要额外规则，再针对性增加，而不是整体覆盖。

## 4. 备选方案：修复交互站点的模式判断

不新增长页面导航，直接让交互站点在 `content:` 等协议下也使用内嵌数据模式：

- 把 `isHttp` 的判断从「协议」改成「页面里有没有内嵌的 `data[id][value]` 载荷」。
- `pushState` 外面加 try/catch；地址栏里的 `?page=` 改成 `#page=`，或者不改地址栏。

优点：导航树、单页显示、侧边栏全是现成的，表格样式不会变，改动小。

缺点：仍然依赖 JS、gzip 解码和 `DecompressionStream`，「某些 App 样式丢失」的问题可能依旧存在。

**取舍**：主方案（3.x）依赖最少，在无脚本的环境里也能降级阅读；备选方案改动更小，但没有解决样式丢失。倾向主方案。

## 5. 实现范围（若确认）

按改动风险从小到大：

1. **表格修正**：移除 `long-page.ts` 中的表格包裹与覆盖，改为作用于原有父容器。
2. **导航数据**：长页面构建时调用 `CascadeContentTree` 取层级，并把「页面 → 树节点」映射传给 `buildLongPage`。
3. **渲染与切换**：生成导航 DOM、section 路由、内联脚本和降级 CSS，不生成上一篇/下一篇控件。
4. **手机 / PC 的导航呈现**：抽屉与侧栏两套 CSS。
5. **链接改写**：跨页链接改成 hash 路由；标题链接保留页内定位。
6. **未收录页面的访问**：保留正文与引用链接，不纳入入口目录。

非入口场景（多文件导出而非级联导出）没有「入口层级」，沿用现有的文件树顺序作为导航。

## 8. 实现与验证记录（2026-10-31）

- 采用 3.x 主方案：所有正文内嵌于一个 HTML，使用普通 `#lp-page-N` / `#pN-M` 锚点，内联脚本按 hash 切换；不调用 `fetch`、History API 或解压 API。
- 级联导航复用 `CascadeContentTree`，保留标题、列表分组、别名、图标、顺序与标题链接。长页面独立读取树模型，不依赖交互侧栏开关。非级联导出复用 `FileTree` 的层级和排序；关闭入口目录解析时不生成目录。
- 按用户修正，目录严格沿用主入口结构，未收录页面不会自动补入。它们继续内嵌并支持引用跳转；重复与循环引用不会改变目录。
- 手机显示悬浮目录按钮与抽屉，桌面显示可收起侧栏；窄屏下桌面样式也切换成抽屉。支持当前项高亮、祖先展开、前进后退、脚注和直接打开标题锚点；移除上一篇/下一篇及相关样式、文案参数。
- 脚本禁用时，正文按导出顺序连续展示，目录仍只保留显式编排的节点并使用普通锚点；打印也展示全部正文。
- 表格沿用原有父节点，只在该节点增加滚动样式；移除新增包裹层、表格 margin 覆盖与手机单元格 min-width。

### 8.1 目录视觉优化（2026-10-31）

- 目录采用独立的界面字体与字号，普通条目使用正文色；统一整行 flex 布局、行高、4px 同级间距与层级缩进，避免笔记主题的链接行高影响目录。
- 选中态使用整行淡色圆角背景与左侧指示条，单行、多行标题均垂直居中；展开控件改为细线箭头，层级辅以淡色引导线。
- 手机抽屉增加宽度、圆角和外侧阴影，打开时隐藏悬浮按钮；标题栏固定在目录顶部，关闭按钮与菜单按钮统一使用 SVG 图标。
- 使用截图中的中文多层结构验证浅色、深色及手机、桌面布局；自动检查多行选中项居中、同级间距一致与目录不横向溢出。


### 8.2 保留正文主题样式（2026-10-31）

- 修复真实导出页面不含 `theme-light` / `theme-dark` 的问题：原有交互站点通过脚本补齐这两个类，长页面剥离脚本后没有补齐。长页面现在直接写入当前 Obsidian 的主题模式及已收集的 Style Settings 类，显式快照覆盖缓存页面的旧主题；不再依赖运行时恢复正文主题。
- 长页面强制内嵌正文 CSS，避免沿用交互站点的外链 CSS 选项导致单文件分享后失效。
- 对 CSS 选择器中的阅读容器、工作区祖先做长页面适配，使原有表格、引用、代码块等主题规则继续匹配；只改选择器，保留 CSS 值、字体、SVG 数据和属性选择器中的字符串。
- 修正测试盲点：导航样例不再提前给正文补上主题类。新增 `test:long-page-styles`，用缺失主题类的真实导出结构、导出选择器映射与浅/深色快照，逐项对照原阅读视图的表格、引用、callout、代码块、语法 token 和行内代码的计算样式。覆盖手机/桌面样式、390px/1280px，以及启用/禁用脚本。


### 8.3 响应式阅读与当前文章搜索（2026-10-31）

- 移除长页面的手机/PC 样式枚举、设置字段与两处导出样式选择；同一个导出文件在 760px 及以下显示抽屉，宽屏显示可收起侧栏。窗口跨越断点时重置抽屉状态，避免缩放或旋转后遮挡正文。旧设置中的样式值不再影响新导出。
- 目录按钮统一为 48px 圆形三横线图标，保留无障碍标签；搜索使用独立圆形放大镜按钮。窄屏正文以 16px 系统字体为默认基准，同时沿用已有字号缩放参数，代码继续使用等宽字体；宽屏沿用原主题字号与字体。
- 搜索只作用于当前显示文章的正文，支持大小写不敏感的字面匹配、跨行内格式匹配、匹配计数、高亮、上一个/下一个、Enter/Shift+Enter 与 Escape。支持中文输入法组合输入；不搜索目录、隐藏内容或其他文章，不使用网络与索引载荷。
- 高亮只包裹文本片段，保留代码 token、链接、粗体和原有标注；清空或关闭时还原正文。正文引用切换文章时按新文章重建匹配；打开目录时收起并清空搜索。无脚本时继续保留原有阅读降级。
- `test:long-page-search` 覆盖 390px/1280px、同一文件跨断点切换、手机字体与按钮、当前文章范围、中文组合输入、字面特殊字符、跨粗体匹配、结果循环、正文还原、引用跳转与无脚本。主题回归在窄屏允许预期的字体/字号调整，继续对照表格、引用、代码等主题样式。
